Competitive on paper, stalling in the POC every time

"If security feels like friction, teams route around it and the system fails."

miniOrange's PAM product had all the features a security buyer would ask about on a discovery call: vaulting, session recording, access policies, discovery, MFA. On paper it looked competitive against CyberArk and Delinea.

Then the prospect would start a POC, their admin would open the product for the first time, and the deal would slow down.

The left nav had 14 items with no task-based grouping. Setting up a single privileged workflow meant jumping between three or four sections that didn't know about each other. "System Users" was where credentials lived. Users lived somewhere else. Discovery would surface 200 accounts and leave the admin to figure out what to do next. When things broke, they broke quietly.

The deal-breaking capabilities were either missing or buried three clicks deep behind labels no one recognised. Our own SEs would sometimes ask me where a feature was during demo prep.

The pieces were all there. Nothing held them together.

The original product. Productivity, Security Risk, Compliance, and Continuity all suffering from the same root cause.

I audited ten real admin scenarios and found four root causes

The instinct on a project like this is to pick the worst screens and redesign them. I pushed back on that for two weeks, because I was fairly sure that redesigning individual screens would just move the confusion around rather than resolve it.

I ran a scenario-driven UX audit across the existing product first. Not happy-path click-throughs. Real operational scenarios pulled from CS call recordings and support tickets: new admin onboarding, break glass elevation during a Sev 1, credential rotation across 200+ accounts, engineer offboarding, and audit log review the morning before a compliance call.

Ten scenarios across four personas surfaced 0 discrete usability issues, which clustered into four systemic root causes. The audit took three weeks and was the most leveraged work on the project.

  1. 01 Fragmented information architecture. 14 flat nav items, no task-based grouping. Admins had to know the product's internal object model to find anything.
  2. 02 Broken domain terminology. Object names didn't match the mental model of any persona. New admins spent their first week translating the interface before using it.
  3. 03 No workflow continuity. Critical paths like JIT, approvals, and break glass either didn't exist or required jumping between disconnected sections.
  4. 04 Silent failure states. Errors weren't surfaced. Discovery found data but didn't guide action. Admins couldn't tell what broke or what to do next.

SC.01 and SC.02 are deal-breaker scenarios

140 issues. Four root causes. The problem was never the screens.

One filter decided what shipped

The PM wanted Kano. The eng lead wanted RICE. We'd run two prioritization frameworks in the previous quarter, gotten different outputs each time, and still had no alignment on what to build next. I suggested something blunter.

I identified five deal-breaker capabilities: the features that, if absent or broken, would lose an enterprise deal regardless of everything else. Vault & Rotation. Discovery & Inventory. Session Proxying & Recording. Access Governance. Integrations & Auditability. Then one binary question for every backlog item: does this directly strengthen one of those five, or not?

A meaningful slice of the backlog was deferred in two days. Three sprints in, the PM called it the most useful prioritization tool we'd used on the product.

Redesigned the system

Three architectural decisions that changed what the product felt like to use, not just what it looked like.

01

Organize by admin intent, not object type

The original nav was organized by database object: System Users, Groups, Certificates, Resources, Policies. The redesign organizes by what the admin is trying to do: Overview, Setup, Access Control, Security Ops, Identity Config. Break glass lives under Security Ops. A new admin can find it on day one without opening the docs.

Before: organized by object

14 flat items
→ 5 intent groups

02

Workflow continuity within the resource

Credential reconciliation was previously a multi-page workflow across four screens. During a 2am incident, that was genuinely dangerous. I embedded it inline in the credential tab: mismatch status surfaces next to the credential record with a single-action resolution. The tabbed resource workspace (Credentials, Policy, Access, Sessions, Audit) all scope to the resource the admin is working on, so they never lose their place.

03

A six-stage onboarding model with checkpoints

Onboarding was a linear wizard with no checkpoints. Admins couldn't tell when they were done. I redesigned it as six stages: Discover, Inventory, Policy, Roles, Provision, Access. Each produces a concrete output: a discovered account list, a configured policy, a role assignment. An admin starting a trial can reach active session proxying and working JIT within the first day.

An edge case that changed the design

Push for a non-linear onboarding path earlier. The six-stage model worked for net-new deployments, but customers migrating from a legacy PAM tool had a different mental model and kept skipping stages. We patched it in v1.2. I should have caught it in the persona research.

A persona is incomplete without knowing what the user is migrating away from.

A coherent platform, not a feature list shipped to production

New PAM revenue unlocked post-launch
$800K

in new PAM sales in the quarter post-release. Deals that had stalled at POC closed once admins could reach a working state inside the trial window. The stall pattern we'd been tracking was gone.

The v1 shipped as a coherent platform. The audit and the prioritization filter gave the team a shared definition of done.

Product outcomes
  • Admins complete critical workflows — onboarding, break glass, rotation, access, audit review — without leaving the resource they're working on.
  • The five deal-breaker capabilities now anchor the product's core experience instead of being buried behind unfamiliar labels.
  • Error states and reconciliation logic surface inline. The admin knows what broke and has a clear action. No more silent failures.
  • The product aligns to Zero Trust, SOC 2, and ISO 27001 principles by architecture, not by adding a disclaimer to the docs.
Team outcomes
  • Engineering had a single prioritization filter that resolved scope debates in one meeting instead of a quarter of framework workshops.
  • Design churn dropped because decisions shifted from "which screen looks better?" to "which system structure supports the workflow?", a question with a more stable answer.
  • PMs, engineers, and design shared vocabulary that cut review cycles to what actually mattered.

What I'd take into the next engagement

Lesson 01

The audit was the whole project

On this one, the three-week scenario audit was the most leveraged work I did. It gave the team a shared, evidence-based picture of what was broken and why. Every design decision after was implementation of conclusions we'd already reached together.

Lesson 02

Prioritization frameworks are conversations, not calculations

RICE and Kano failed here not because they're bad frameworks, but because the team was using them to avoid a conversation about values. The binary deal-breaker filter worked because it forced that conversation and gave it a concrete output.

Lesson 03

In security products, usability is a security control

The product that is easy to use correctly is more secure than one with better features that is hard to use. Every time an admin routes around a broken workflow, that workaround is a shadow credential, a compliance gap, a potential breach. The UX isn't decoration on top of the security model. It's load-bearing.

When you fix the system, not the symptoms, the numbers follow.
