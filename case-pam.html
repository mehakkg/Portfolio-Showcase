✦The Problem

Strong bones, no spine to hold it together

miniOrange's PAM product had everything a buyer's checklist asks for. Vaulting, session recording, access policies, discovery, MFA. On a feature comparison spreadsheet, it looked competitive.

Every admin who tried to actually use it hit the same wall.

The product was 14 disconnected nav items masquerading as an ecosystem. Setting up a single privileged workflow required jumping between three or four unrelated sections. Object names contradicted what admins actually meant. "System Users" was where credentials lived, not users. Errors happened silently. Discovery surfaced data but didn't guide action. Critical enterprise capabilities like JIT access, emergency break glass, session OCR, reconciliation were either missing or buried so deep that customers assumed they didn't exist.

The result was a product with strong bones and no spine.

✦Why It Mattered

Bad UX in PAM isn't just frustrating — it's a vulnerability

In consumer software, bad UX costs engagement. In PAM, it costs the entire security posture.

The core paradox of Privileged Access Management: the harder it is to use, the less secure it makes you. Admins under deadline pressure don't file tickets when a workflow is broken, they route around it. A DevOps engineer who can't get JIT access in under a minute will just use their standing admin credentials. Every workaround becomes a shadow IT vulnerability. Every friction point becomes an audit finding.

At the business layer, enterprise deals stalled in POC because admins couldn't set up meaningful workflows inside a trial window. Support fielded repetitive tickets on setup steps that should have been self serve. Compliance customers failed audit prep because the product didn't produce audit ready evidence out of the box.

The product wasn't failing because it lacked features. It was failing because the features didn't hold together as a system.

✦How I Solved It

Systems problem, not a screens problem

Three phases. Diagnose, prioritize, rebuild.

Phase 01 — Diagnose before designing

Before touching a single wireframe, I ran a scenario driven UX audit across the existing product. Not happy path click throughs. Real operational scenarios: onboarding a new admin on day one, break glass elevation during a Sev 1, credential rotation across 200+ accounts, offboarding a departing engineer, walking an auditor through a 90 day activity log.

Ten scenarios. Four personas: Security Admins, IT Operations, DevOps and SysAdmins, Compliance Officers. 140+ usability issues surfaced — clustered into four systemic root causes:

Root cause 01

Fragmented information architecture

14 flat nav items, no task based grouping. Admins had to know the product's internal object model to find anything.

Root cause 02

Broken domain terminology

Object names didn't match the mental model of any persona. Every new admin spent their first week translating the interface before they could use it.

Root cause 03

No workflow continuity

Critical paths like JIT, approvals, break glass either didn't exist or required jumping between disconnected sections.

Root cause 04

Silent failure states

Errors weren't surfaced. Discovery surfaced data but didn't guide action. Admins couldn't tell what broke or what to do next.

Phase 02 — A binary prioritization filter

The engineering team had been stuck in framework debate for months. Kano models, MoSCoW, RICE. Every exercise produced a different answer and no forward motion.

I collapsed the whole thing to one binary question: does this strengthen a deal breaker capability, or doesn't it? Deal breakers: Vault & Rotation, Discovery & Inventory, Session Proxying & OCR, Access Governance (RBAC and JIT), Integrations & Auditability.

Two days of alignment. A meaningful portion of the v1 backlog cut without a single status meeting.

✦Architecture

Redesign the system, not the screens one by one

Three architectural decisions that changed what it felt like to use the product.

01

Experience architecture over feature list

The old product organized itself by internal object type: Users, Groups, Certificates, Resources, Policies. The redesign organizes itself by admin intent: Overview, Setup, Access Control, Security Ops, Identity Config. A new admin can now find break glass because it lives where break glass belongs.

02

Workflow continuity within the resource

Instead of forcing admins to piece a workflow together across separate pages, I built the resource detail as a tabbed workspace. Overview, Credentials, Policy, Access, Sessions, Audit trail — all scoped to the resource they're working on. The admin never loses context.

03

A six stage onboarding model

I redesigned admin onboarding as six discrete stages: Discovery, Inventory, Policy, Roles, Provisioning, Access. Each stage produces a verifiable checkpoint — no more setup wizards where you can't tell if you've done it right.

✦Outcome

A coherent platform, not a feature list shipped to production

The v1 shipped as a coherent platform, not a feature list.

Product outcomes
  • Admins complete critical workflows — onboarding, break glass, rotation, access, audit review — without leaving the resource they're working on.
  • The five deal-breaker capabilities now anchor the product's core experience.
  • Error states and reconciliation logic surface inline instead of hiding in documentation.
  • The product aligns to Zero Trust, SOC 2, and ISO principles by architecture, not by disclaimer.
Team outcomes
  • Engineering had a single prioritization filter that resolved scope debates in minutes instead of quarters.
  • Design churn dropped significantly by moving decisions from "which screen?" to "which system?" early in the process.
  • PMs, engineers, and design shared a common language that cut review cycles down to what actually mattered.
✦Lessons

What I'd take into the next engagement

Lesson 01

Audit against scenarios, not screens

Happy path heuristic reviews miss the failures that matter. Audit against what the user is actually trying to do and the real friction surfaces immediately.

Lesson 02

Prioritization is a communication problem

No framework fixes a stakeholder disagreement. What fixes it is a single, binary question everyone can answer the same way.

Lesson 03

Usability is a security control

Every friction point pushes a user toward a workaround. Every workaround is a vulnerability. Design decisions in PAM aren't cosmetic — they're part of the threat model.
